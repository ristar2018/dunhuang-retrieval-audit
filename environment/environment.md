file written afterwards. Versions are exact; the platform line is the machine
that ran everything.

runtime, fp16/BF16 mixed precision, batch size 32. Training a single run of the
published grid takes 12–60 s depending on tier; the 450-run cross-fitted grid
takes about 6 hours of wall clock.

## Backbone

`data/features/feature_index.json` pins the feature extractor:

```
model            dinov3-vitb16-pretrain-lvd1689m
feature_dim      768
input_size       224
normalized       true
num_images       32415
```

Features were extracted once, frozen, and reused by every run. No run fine-tunes
the backbone — this is a property of the design, not a runtime accident, and it
is what makes the 628 configs comparable.

## Determinism

- Training seeds fix weight initialisation and batch order.
- The five cross-fitting folds are fixed by `code/stage0/e1_make_splits.py` and
  their membership is in `data/gradients/` plus the fold definitions in
  `code/stage0/e1_build_folds.py`; folds are contiguous near-duplicate
  components, not an i.i.d. shuffle, so they do not depend on a seed.
- The four size-matched control sets are fixed by explicit index lists
  (`data/gradients/S0_prime..S3_prime_indices.json`), not by a sampling seed, so a
  run is reproducible from its `training_set` value alone.
- CUDA nondeterminism is not pinned (`torch.backends.cudnn.deterministic` was
  left at its default). Re-running a config reproduces the reported MAP to about
  the third decimal, not bit-exactly; the paper's claims rest on differences
  several times larger than that. This is a limitation of the package, stated
  rather than hidden.

## LaTeX (manuscript and supplementary build)

TeX Live 2026, `pdflatex` + `bibtex`, Springer Nature `sn-jnl` class with
`sn-mathphys-num.bst`, both copied into `code/build`'s sibling directory in the
working tree. The manuscript builds with the class file from the journal
template; figures are PDF, vector, generated by `code/build/make_figs.py` at
